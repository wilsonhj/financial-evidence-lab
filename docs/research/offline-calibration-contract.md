# Offline calibration primitives: frozen external implementation contract

Frozen September 16, 2026 under accepted ADR-0028; external issues #336/#337, integration #333. Baseline inspected: `public-guard-control` at d4fd138. No calibrator/dataset validator exists: current worker creates `record_confidence=None`, empty field confidences, and validator-derived review priority. Preserve that behavior. ADR-0007/spec003 require isotonic-v1; September16 completion proposal leaves split, score and metric details awaiting freeze. This document freezes only the offline interchange and numerical primitives; it is not live calibration evidence or permission to integrate runtime scoring.

## Frozen shared interchange

Lead owns this interchange contract and issue registrations. Both agents consume its immutable JSON shape, not each other's implementation. No shared Python types module is necessary. Use only standard-library arithmetic/parsing; no dependencies, DB, provider calls or runtime integration. Keep worker imports and existing confidence tests unchanged.

Dataset `extraction-calibration-dataset/v1`: exact keys `schema_version`, `dataset_id`, `evidence_kind`, `pins`, `split_manifest`, `records`. `dataset_id` is a canonical lowercase UUID. `evidence_kind` is `synthetic` or `adjudicated`; synthetic remains conspicuously marked through every output. Pin keys are `ontology_sha256`, `workflow_sha256`, `prompts_sha256`, `model_sha256`, `score_definition_sha256`; values are lowercase 64-hex SHA256, representing immutable manifests rather than hash-like free-text model names. A score-definition manifest fixes meaning/producer of the uncalibrated signal; no model confidence field or raw-score producer is introduced here.

Split manifest has exact keys `train`, `calibration`, `evaluation`, each containing `issuer_ids`, `start_at`, `end_at`. Each issuer list is sorted unique canonical UUIDs and nonempty; issuer sets are pairwise disjoint. Times use exact UTC second strings YYYY-MM-DDTHH:MM:SSZ. Windows are inclusive, nonempty and strictly chronological: train.end < calibration.start; calibration.end < evaluation.start. No random split, reassignment, issuer balancing, or choosing a cutoff after observing results. Dataset validation proves declared allocation, not that reviewers preregistered it; signed human preregistration remains outside these packages.

Records have exact keys `sample_id`, `proposal_sha256`, `issuer_id`, `source_sha256`, `published_at`, `as_of`, `adjudicated_at`, `split`, `family`, `field`, `score`, `outcome`, `reviewer_ids`. Sample/issuer/reviewer IDs are canonical lowercase UUIDs; hashes are lowercase64hex. Families: `kpi`, `guidance`, `revenue_driver`; field matches `[a-z][a-z0-9_]{0,63}` and denotes an independently calibrated field, never a free-text source value. Score is a string in [0,1] with at most12 fractional digits, no exponent/sign/leadingzero, using canonical trailing-zero-free spelling; outcome is an actual integer0or1, never bool. Two distinct sorted reviewer IDs are required for adjudicated records; synthetic records use empty reviewer lists and may not claim human review. No source text, provider responses or personal reviewer names enter this interchange.

Each record belongs to its declared split issuer set and publication-time window; published_at <= as_of <= adjudicated_at. Across splits, max(train.as_of) < min(calibration.published_at) and max(calibration.as_of) < min(evaluation.published_at) when nonempty, preventing later pinned context from crossing an earlier split boundary. Identity uniqueness is both sample_id and (proposal_sha256,family,field); one proposal hash cannot occur in multiple splits. One source hash cannot occur in multiple splits. Repeated fields of one proposal are allowed only under distinct field names, same issuer/split/source/time values. All rows share top-level pins. Versioned provider score-generation and source evidence validity are upstream responsibilities; the loader cannot verify a filing from a hash alone.

Canonical bytes: recursively sorted JSON object keys, UTF8, ensure_ascii=False, separators comma/colon, no whitespace/trailing newline; records sorted by sample_id, all set-like lists sorted; no floats/nonfinite numbers/duplicate JSON keys. Dataset SHA256 hashes these canonical bytes, not input whitespace. Bound input to64MiB,100000records,1000issuer IDs per split and10000 total strata; reject excess before unbounded work. Top-level unknown keys/row unknown keys fail closed.

Readiness is per (family,field) in each declared split: at least100 rows, at least20 outcome0 and20 outcome1. Report insufficient cells, do not drop them or pool families/fields. A stratum must satisfy calibration support to fit; held-out evaluation support is required for an evaluation-ready report. Train support is reported but no model training runs here. Support-report ready means every observed stratum has sufficient calibration and evaluation support. Train support is reported but does not gate this offline readiness flag. This is not release readiness and adds no release-gate claim. No count threshold claims empirical quality.

## Package CAL-PAV — external agent B, independent of A

Exclusive files: `workers/src/fel_workers/extraction/isotonic.py`, `workers/tests/extraction/test_isotonic.py`, `workers/src/fel_workers/extraction/ISOTONIC.md`. No edits to worker stages/types/persistence/OPERATOR or existing tests.

Pure APIs: `fit(samples: Sequence[tuple[str,int]]) -> dict[str, object]`; `predict(artifact: dict[str,object], score: str) -> Decimal`; `evaluate(artifact, samples) -> dict[str,object]`. These APIs accept one stratum's calibration/evaluation inputs only; orchestration attaches family/field/pins/dataset hashes in a later integration package. Input score/outcome syntax and100/20/20 support match the frozen interchange. An independent agent can implement from tuples without importing A. Bound samples at100000. Invalid inputs raise fixed `CalibrationError` codes `invalid_sample`, `limit_exceeded`, `invalid_artifact`; do not silently coerce bool/float or omit bad rows.

Algorithm: sort by exact Decimal score, aggregate tied score counts/positives, then weighted pool-adjacent-violators. Merge neighboring blocks while left positives/count > right positives/count, comparing integer cross-products; continue until monotone. Canonically coalesce equal adjacent means too. Each output block stores canonical decimal lower_score,upper_score and integer count,positive. No weights other than sample multiplicity, smoothing, interpolation, epsilon, randomization or sklearn dependency. Integer counts define exact rational means; use isolated Decimal precision50 and ROUND_HALF_EVEN quantization to12 decimal places for returned probabilities/metrics. Ambient Decimal context must not affect outputs.

Fit artifact exact shape: schema_version `isotonic-v1`, status `fitted` or `insufficient_data`, n,positive,negative, blocks(list). Insufficient support yields emptyblocks; predict returns Decimal('0') for that artifact. This is explicitly attempted-but-insufficient scoring, distinct from historical runtime NULL; do not write it to existing proposals. Fitted block counts total n/positive; require strictly ordered disjoint score intervals, monotone reduced-rational means, bounded valid counts, and no adjacent equal means. Validate artifacts on predict/evaluate, including support/status consistency.

Prediction: within a block, use its positive/count. Between blocks use the block whose lower_score is the greatest <= query (left step); below minimum clamp first; above maximum clamp last. Exact boundaries and tie policy are frozen, not inferred by a library. Return12-place Decimal probability. A missing calibrator is not an artifact and raises invalid_artifact, never pretends unscored is scoredzero.

Evaluation never refits. Exact result keys: schema_version=`isotonic-evaluation/v1`, status (`evaluated`, `insufficient_calibration`, `insufficient_evaluation`), n,positive,negative,sufficient,brier,ece,bins. sufficient is true exactly for evaluated; brier/ece are12-place decimal strings or null. Successful bins are10 ordered objects with exact keys index,count,mean_probability,positive_rate (12-place strings or null for empty bins). Insufficient results have bins[] and null metrics. Use held-out inputs passed by caller; Brier/ECE use10equal-width bins [0,.1),...,[.9,1]. Bin index=min(9,floor(10*p)); emptybins count0 with null means. Brier=sum((p-y)^2)/n; ECE=sum(bin_count*abs(mean_probability-mean_label))/n. Compute exact Fractions from the12-place predictions and integer labels, then emit12-place decimal strings. If evaluation support insufficient, metricsnull; if fitstatus insufficient, metricsnull regardless evalcount. Include explicit status `insufficient_calibration` or `insufficient_evaluation` instead of fakezero metric. Calibration/evaluation identity and no-leakage checks belong A plus later orchestrator, not this numerical primitive.

First failing tests: decreasing outcomes force pooling; tied scores grouped before PAV; constant score with bothclasses; weighted pooling must use counts; exact known pooled fraction oracle; permutation stability; monotonic predictions; lower/upper/gap boundary/extrapolation;100/20/20 vs99/19 support; malformedartifact wrongtotals/overlappingblocks/nonmonotonicmeans; isolated Decimalcontext; exact Brier/ECE oracles including p0,p1,.1 edges andemptybins; insufficient metricsnull. Generate enough synthetic repetitions to meet real support thresholds—no test-only production bypass.

## Integration and acceptance limits

Both packages may dispatch simultaneously from the immutable base specified in the implementation handoff; their exact paths are reserved for external owners. Neither integrates runtime scoring, chooses raw-score producers, edits policy thresholds, trains on evaluation labels, performs provider calls, persists calibrators or human-adjudicates labels. Later single-owner integration consumes A's validated split, calls B.fit only on calibration rows, evaluates only held-out evaluation rows, combines dataset/pins/calibrator-codehash with blocks and metrics, and computes final artifact hash excluding its own hash field. That later contract owns record-minimum required-field scoring, citationfailurezero, historicalNULL, policy audit, persistence and no-auto-approval proofs. Passing synthetic tests leaves #62's human/live/release gates open.


## Additional strictness and completion rules

Accept UTF-8 JSON without BOM; all public dataset functions validate exact object/type shapes, including actual integers rather than bool. UTF-8 errors, duplicate keys and nonfinite JSON are invalid_json. Canonical input dict validation rejects floats anywhere. Bound nesting while decoding and return a fixed safe error for recursion/size failures; never print supplied data. Dataset bytes may contain whitespace, but canonical output does not. Observed strata are the union across all rows, so missing calibration/evaluation cells are explicitly zero.

Score canonical spelling is `0`, `1`, or `0.` followed by 1–12 digits with a nonzero last digit. Dates are real UTC instants, not merely regex matches. Within one proposal, issuer/source/publication/as-of/adjudication/split metadata must agree. Reviewer IDs are opaque synthetic UUIDs in tests; a syntactically adjudicated fixture never establishes actual human adjudication. No package fetches source documents or validates their contents from hashes alone.

For PAV sequences accept list/tuple of two-element list/tuple rows only (not strings/generators); outcome must be an actual int0/1. Empty valid input is insufficient, not invalid. Counts are nonnegative actual ints bounded100000; fitted blocks have count>=1 and 0<=positive<=count, exact artifact keys and canonical endpoint scores. Total counts/classes, support/status and block ordering must agree. Schema/status strings are closed enumerations. Samples and artifacts remain unchanged after calls. Dataset/predict errors do not include raw values or exception chains.

No implementation touches existing worker entrypoints, imports/exports, confidence storage or thresholds. Return commit/patch, exact test commands/results, changed-path list and limitations to the lead. Required integration review and CI remain; do not close #62 or mark any canonical task complete.

Maximum JSON/dict nesting is16 containers, counting the root object as1; deeper input raises limit_exceeded (including recursion-limit decoding failures). evaluate validates both artifact and samples first, then insufficient_calibration takes precedence over insufficient_evaluation when both lack support. An invalid prediction score raises invalid_sample.
