# Public authentication and BYOK contract proposal

Status: **Proposed contract, pending independent review and shared-contract freeze.** Design deliverable for #324 under ADR-0026; not permission to implement blocked runtime or provision paid resources. No OpenAPI, migration, dependency or runtime change is made by this document. Public signup/private workspaces and user-funded OpenRouter-first inference are accepted direction; the interfaces below are proposed implementation decisions.

## Inspected boundary and selected architecture

Inspected current `apps/api/app/{supabase_auth,dependencies}.py`, web reader/Observatory runtime configuration, extraction transport and migration0001 through0011. The API already verifies asymmetric Supabase tokens and rechecks database membership, but requires `app_metadata.org_id`. The web currently supplies a deployment bearer and fixed workspace/entity configuration. A fresh public signup cannot use that tenant verifier before trusted organization provisioning. Public request handling must therefore not merely forward the old configured token.

Choose a backend-for-frontend session: Next owns an opaque browser session handle; Supabase access/refresh tokens remain encrypted server-side. Use the maintained `@supabase/supabase-js` SDK in server-only request-scoped clients with persistence, URL-session detection and automatic background refresh disabled; explicitly call supported signup/password-login/verification/refresh/signout methods. Do not install a browser Supabase client or duplicate SDK token-refresh logic. This differs deliberately from browser-readable SSR token cookies: the browser receives only the application's opaque handle. Exact dependency pins are chosen from supported versions during reviewed lockfile change, not invented here.

Next forwards the verified session's Supabase access token only to its fixed configured FastAPI origin. It never forwards browser-supplied Authorization, upstream URL, organization header or deployment bearer. API validates the token independently. Separate identity verification from tenant resolution: `VerifiedIdentity(user_id, session_id, issuer, expires_at)` verifies the same signature/issuer/audience/time constraints; `resolve_context(identity, requested_org_id)` checks actual membership and returns existing `TenantContext`. Requested organization is a selector, never a privilege claim. Keep the existing `verify()` compatibility adapter and mock mode while migrating callers under tests; never make ordinary tenant endpoints accept missing organization context implicitly.

## First independently dispatchable slice: deployment guard

Proposed new environment discriminator `FEL_DEPLOYMENT_MODE=public|fixture|reader-smoke`. Missing value resolves to `public`; unknown values fail closed. Do not derive trust from NODE_ENV, a request header, hostname or a query string.

| Mode | Allowed behavior |
|---|---|
| public | Requires HTTP data, Supabase API verifier and request-scoped sessions. Configured deployment bearer/fixed workspace bindings are rejected for business requests. Until public sessions are implemented, fail with generic503 `PUBLIC_AUTH_NOT_READY`; never serve another identity's data. |
| fixture | Explicit synthetic fixture data only, no live upstream credentials or billable network calls. Public feature routes cannot switch to fixture on error. |
| reader-smoke | Explicit dedicated smoke target/manifest binding and existing opt-ins; deployment bearer remains solely for that isolated synthetic workflow. It does not establish public auth acceptance. |

Guard all three readers of deployment identity: evidence runtime, Observatory runtime and extraction transport. Cover server components and proxy routes, not only login pages. Update local fixture/browser and dedicated smoke harness environment declarations in the same registered integration slice so legitimate tests are not broken by the new public default. API public mode rejects mock auth; smoke opt-in remains explicit. Startup diagnostics name missing configuration only, never values. First slice adds no cookies, vault, migrations, signup UI or provider calls.

Candidate ownership: new `apps/web/src/lib/deployment-mode.ts` and tests; named reader/Observatory/extraction runtime configuration and corresponding tests; exact API config guard/tests; explicitly enumerated harness configuration files. Root assigns the actual paths before dispatch; new shared settings/schema changes are a separate contract slice. Acceptance: public+shared bearer cannot issue any upstream request; unset/unknown modes fail closed; explicit fixture works offline; dedicated smoke works only with its existing target checks; production mock tokens fail; every integration seam covered by a test.

## Proposed browser and API interfaces

All browser mutations require same-origin Origin validation, a session-bound CSRF token, JSON content type, bounded body and fixed routes; login/signup use an anonymous pre-auth handle and CSRF token to prevent login CSRF. Cookie is `__Host-fel_session`, HttpOnly, Secure, SameSite=Lax, Path=/, no Domain. Development loopback uses a separately named explicit development cookie, never weakens hosted settings. Rotate the handle on successful authentication and privilege-context changes; store only its SHA-256 digest. Responses containing auth/user data are `Cache-Control: private, no-store`; no CDN/shared Next cache for personalized fetches, and cache identities include user/org/workspace/pins where private caching is separately approved.

| Endpoint | Request → response and behavior |
|---|---|
| `GET /api/auth/session` | Metadata `{authenticated,user_id,org_id,workspace_id,csrf_token}` or anonymous state; never tokens. Creates pre-auth handle when needed. |
| `POST /api/auth/signup` | `{email,password}` →202 generic email-verification instructions. SDK email confirmation remains required. Never return an existence oracle or store password. |
| `POST /api/auth/login` | `{email,password}` →200 metadata after verification/bootstrap; generic401 on invalid credentials. No browser-provided org/role accepted. |
| `POST /api/auth/verify` | `{token_hash,type}` with allowlisted verification/recovery types → metadata or generic failure. Consume once; do not log request bodies. Confirmation links terminate at a first-party no-store/no-referrer page, submit immediately and clear URL state; no analytics before cleanup. |
| `POST /api/auth/recovery` | `{email}` →202 generic result; fixed approved redirect destination. |
| `POST /api/auth/password` | `{password}` using verified recovery context →204; rotate/revoke app sessions and follow SDK recovery policy. |
| `POST /api/auth/logout` | No body →204; invalidate app session immediately, then SDK signout/revocation; provider outage cannot keep local session valid. |
| `POST /v1/onboarding` | Identity-only bearer plus authoritative confirmed-email verification; body `{}` + Idempotency-Key → existing/new `{org_id,role:"owner"}`. Does not accept owner/user/org IDs. Workspace creation is a separate existing API operation with user-selected valid entities, currency and fiscal calendar; bootstrap invents no workspace defaults. |
| `GET /v1/me` | Verified identity → own memberships/workspace summaries through bounded pagination; no arbitrary-user selector. |
| `POST /api/byok/openrouter/authorize` | `{label}` →303 fixed OpenRouter authorization URL with S256 challenge and exact callback binding. Require authenticated session, CSRF and privacy-policy disclosure. |
| `GET /api/byok/openrouter/callback` | One-time provider code plus bound transaction token → server exchange, encrypted credential insertion,303 fixed settings route. No key in redirect/response. |
| `GET /v1/me/credentials` | Bounded metadata `{id,provider,label,status,version,created_at,validated_at,revoked_at,capabilities}`; no key/prefix/ciphertext. |
| `DELETE /v1/me/credentials/{id}` | Owner-only idempotent local revocation →204; mark unusable before best-effort provider-side revocation. Missing/foreign credentials yield same404. |
| `POST /v1/me/credentials/{id}/validate` | Metadata-only check using a nonbillable provider capability endpoint; if unavailable return typed failure, never send a paid test prompt. |

Direct key capture is a subsequent reviewed endpoint, not implemented in OpenRouter-first slice. Future create/replace accepts key only in a redacted POST body; replacement creates a distinct immutable credential version and revokes the old version. Never retarget queued runs to a new key automatically. Existing execution endpoints gain a frozen `credential_binding` admission field only in a later contract slice; no independent TS mirrors or unversioned job payload additions.

OpenRouter PKCE transaction stores user/session/org, verifier ciphertext, exact callback and consumed state. Bind callback to the initiating authenticated session and a high-entropy one-time transaction token embedded in the predeclared callback URL; verify the provider's exact callback preservation in contract tests. A lost/mismatched session, replay, expired transaction or substituted callback fails without persisting any key. Never rely on an unsupported OAuth `state` roundtrip. Do not log callback query strings or collect traces there. Server exchange uses fixed OpenRouter endpoints without redirects to untrusted origins.

## Persistence, isolation and trusted provisioning

Additive migration, number allocated by lead, contains:

- `private.web_sessions`: handle digest, verified user/session IDs, encrypted access/refresh payload, expiry/revocation and version. No browser/Data API grants. A dedicated narrowly privileged BFF DB role alone manages session rows; its credentials cannot read business tables or provider credential payloads. Serialize refresh with row lock/version comparison; persist rotated refresh token atomically. Failed/reused refresh invalidates local session rather than retrying an obsolete token indefinitely. Application expiry cannot exceed configured Supabase session policy; use SDK expiry metadata, not invented lifetime defaults.
- `private.auth_transactions`: pre-auth/verification/PKCE one-time transactions, session binding, expiry and encrypted verifier. Exact limits/lifetimes come from the frozen auth/provider policy. No unauthenticated listing. Cleanup removes expired material without exposing it.
- `user_onboarding`: unique user→personal organization mapping, server-generated IDs and status. Bootstrap endpoint uses a dedicated provisioning role with minimum insert/select rights and identity-scoped forced RLS, never a general Supabase service key exposed to Next/browser. In one DB transaction allocate organization, initial owner membership, mapping, audit and receipt. Concurrent login returns the same mapping. A removed/suspended membership is not recreated by replayed onboarding; status fails closed. Before provisioning, validate the signed identity and query the trusted Supabase Auth endpoint with the user token to require its authoritative email-confirmed state; fail closed on missing confirmation or upstream failure. Editable metadata cannot establish verification. Existing organization members may retain their existing authorized context; migration must explicitly map existing identities rather than create duplicate organizations blindly.
- `provider_credentials`: UUID, org, owner user, provider, label, lifecycle state, immutable version, ciphertext/encryption metadata, capability/privacy-policy reference and timestamps. Composite membership reference restricts scope. Forced RLS authorizes metadata by both organization and owner, not org alone. Separate secret payload access grants from metadata views; app/browser roles cannot select plaintext or ciphertext. Audit lifecycle without secret material.
- `run_credential_bindings`: immutable run/org/workspace/initiating-user/credential-version/model-route/privacy-policy/budget-reservation references. Queue payload carries only this reference and existing identifiers. Foreign keys prevent cross-user/org/workspace binding; worker admission rechecks effective membership, run owner, credential ownership/status, route/privacy eligibility and approved budget before each attempt.

Business data remains accessed by existing `fel_app`/`fel_worker` boundaries with explicit tenant claims. New private tables are not exposed through Supabase Data API. Use FORCE RLS, explicit role grants, no PUBLIC grants and no broad SECURITY DEFINER workaround. A bootstrap role is intentionally separate from ordinary API role and cannot edit arbitrary existing organizations/memberships. Freeze and test its policies before implementation.

**Narrowed encryption amendment (proposed contract):** use the already hash-locked `cryptography==50.0.1` Python library's Fernet/MultiFernet behind `SecretCipher.seal(payload)`, `open(ciphertext, expected_identity)` and `rotate(ciphertext)`. This is maintained-library symmetric authenticated encryption, **not envelope encryption**. It replaces this draft's AWS Encryption SDK/KMS proposal and requires a narrow ADR-0026 wording amendment before implementation. Supply the server-only keyring through the existing approved deployment secret store, entirely outside PostgreSQL, source and logs. No AWS platform, provisioning, hand-written cipher, envelope protocol or password-derived key is introduced.

Encrypted JSON includes schema, purpose, organization, owner user, provider and credential ID/version (or session ID for session purpose). After authenticated decryption, strict decoding compares every identity against the authorized database row before secret release. These fields are authenticated plaintext inside the ciphertext; Fernet has no separate AAD API. Swapped ciphertext fails identity comparison. Database possession alone cannot decrypt; compromise of the running application/keyring can expose decrypted secrets and is not prevented by encryption at rest. Provider plaintext is accessible only in isolated custody/invocation code, never metadata serializers or key-read APIs. No key-storage API ships before migration freeze.

New writes use the first MultiFernet key. Rotation prepends a library-generated key, re-encrypts rows with `rotate`, preserves identity checks and emits secret-free audit. Keep old decrypt keys until all retained rows are re-encrypted and backup/restore proof establishes required retained material remains recoverable. Do not delete keys just because active rows migrated. Missing/malformed keyring or invalid ciphertext fails closed. Offline fake cipher is rejected in production. Python custody owns crypto: the session child must freeze a server-authenticated purpose-scoped BFF/custody interface for encrypted Supabase session storage, not an ad-hoc JavaScript Fernet port. That interface cannot read provider credentials and exposes no generic decrypt operation.

Workers may decrypt only the credential bound to their admitted run through the custody service boundary; queue messages never contain keys or Supabase tokens. Rotation/revocation races are serialized at invocation admission. Revocation blocks every subsequent invocation/retry; already transmitted provider requests cannot be recalled and are recorded as in-flight at revocation. Do not promise cancellation of a remote charge already incurred. Missing user key is never repaired with an operator key.

## Cost and error contract

Reuse existing error envelope and budget policy. Proposed additions are closed codes with safe messages:401 `UNAUTHENTICATED`;403 `CSRF_REJECTED` or existing membership denial;404 `NOT_FOUND` for foreign/missing credentials;409 `CREDENTIAL_REVOKED` or binding-version conflict for an owned revoked binding;422 `CREDENTIAL_REQUIRED`, `PROVIDER_CAPABILITY_UNAVAILABLE`, `PROVIDER_POLICY_REJECTED`; existing budget-exceeded status/code for durable user/org ceilings;503 `AUTH_UNAVAILABLE`, `CREDENTIAL_STORE_UNAVAILABLE`, `PUBLIC_AUTH_NOT_READY`. Upstream credit exhaustion is mapped to an owned-credential actionable error without exposing provider response text. Exact new status/code mapping is frozen together with clients before runtime dispatch; do not overload missing credentials as a free fallback.

Admission binds all billable generation, embedding/index, verification, retry and background work to initiating user's credential and budget. Reserve maximum authorized cost before issuing a request, reconcile actual usage afterward and retain reservations conservatively when outcome is unknown. Reuse existing prices/caps/approval requirements; this proposal adds no new numeric spend defaults. A background task with no initiating funded identity remains blocked. Shared public corpus content does not authorize shared payer credentials or cross-tenant provider data redistribution.

## Small delivery packages and acceptance

1. **Guard child:** only deployment discriminator and all fixed-bearer entrypoint checks plus explicit fixture/smoke configuration. No schema/SDK/cipher dependency; regression proves zero upstream requests from unauthenticated public mode.
2. **Contract child (lead writer):** proposed API/session/identity/credential/job contracts, additive migration and exact roles, dependency/platform ADR, generated types. Preserve current verifier adapter. Migration harness proves empty/representative restore, removed-member onboarding, duplicate login, cross-user/tenant secret denial and no PUBLIC grants.
3. **Session/bootstrap child:** SDK server session lifecycle, trusted provisioning, identity-only verifier extraction and request-context plumbing. Two real identities prove all reader/Observatory/extraction paths use their own context. Test CSRF/login fixation, logout, refresh races/replay, recovery, account/member removal, cache separation and no secret-canary outputs.
4. **Custody/OpenRouter child:** reviewed cipher adapter, PKCE, ownership metadata and revoke flow. All tests mock remote transport. Test mismatched callback/session, replay, keyring failure/identity substitution, wrong owner, provider denial, rotation and redaction. No paid test calls.
5. **Billable admission child:** frozen execution bindings, privacy allowlist, durable reservation/reconciliation and worker rechecks. Test revoked key between enqueue/call, canceled/suspended member, stale retry, exhausted credits, unknown prices, altered run binding and no owner fallback across every AI lane.
6. **Hosted acceptance:** provision approved Supabase/secret-store/OpenRouter capability and deployment policy through owner-managed secret flow; exercise real signup/recovery/two-user/private-workspace isolation and authorized user-funded calls only with explicit budget. Existing #108 mock smoke is complementary, not public-auth proof. No public rollout until this passes.

Root freezes exact file allowlists before each child; session, secret and billing seams never have concurrent writers. No package in this proposal is marked dispatched or complete. Scope excludes organization invitations/team administration, arbitrary provider URLs, subscriptions, app-funded quotas and provider/model promotion.
